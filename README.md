# Sage Private Briefs — a Terminal 3 privacy layer for Sage

**Live demo:** https://sage-terminal3.surge.sh
**Sage (Base Stocks):** https://sage-base-stocks.surge.sh
**Built for:** [Terminal 3 Build+Scale Agent Micro Grant](https://dorahacks.io/hackathon/t3-build-scale-grant/detail) ($1,800 pool, deadline 24 Dec 2026) — theme: AI agents working with sensitive/private information via the Terminal 3 Developer Platform.

Sage is a research agent for tokenized stocks on Base: live Chainlink prices, deterministic sourced briefs, a paper portfolio, and a public onchain anchor (the brief's hash on Base Sepolia). This repo adds the **private** half: the same brief sealed into a tenant-private TEE key-value map, and rewritten by Gemini **inside the enclave** — the Gemini API key and the full brief never touch the browser or the CLI.

## The privacy story in one paragraph

A research brief has two halves: a *public commitment* (its hash, anchored onchain so anyone can verify the brief existed) and *private content* (the full text, which may contain a user's positions, notes, or watchlist). Sage already did the public half. This repo does the private half on Terminal 3: `seal-brief` stores the full brief JSON only in the tenant's private `z:<tid>:briefs` KV map under its SHA-256 content address (and publishes that digest as the transaction's claims digest, so the seal lands in the Merkle leaf and is verifiable offline); `private-rewrite` reads the sealed brief back inside the enclave, calls Gemini with an enclave-held API key, and returns only the rewritten text. The key never crosses the WIT boundary, never appears in a log, and never touches the browser — the browser's own AI-rewrite section is the non-private alternative, kept for comparison.

## What the T3 integration actually does

| Piece | What it is |
|---|---|
| `contract/` — `sage-private-brief` v0.1.0 | Rust WASM component (WIT world `sage-private-brief`). Imports `tenant-context`, `logging`, `kv-store`, `http` only. Exports `seal-brief` + `private-rewrite`. Pure-Rust SHA-256 (no extra crate, so the build can't fail on a registry fetch). |
| `seal-brief` | Input `{ symbol, brief }` → canonicalizes the brief (key-sorted JSON), SHA-256s it, stores it in private map `briefs` under the hash, sets the claims digest, returns `{ key, symbol, bytes, map, sealed_at_secs }`. Only the hash + metadata cross the boundary. |
| `private-rewrite` | Input `{ key, instruction?, model? }` → reads the sealed brief + `gemini_api_key` (from private map `secrets`) inside the enclave, POSTs to `generativelanguage.googleapis.com` with the key as a header, returns `{ key, model, text, prompt_tokens, output_tokens, total_tokens }`. |
| `t3/cli.mjs` | Node CLI for the whole lifecycle (see below). Follows the T3 docs exactly: Quickstart auth, `TenantClient`, `maps.create` with `readers`/`writers: { only: [contractId] }`, `contracts.register` + `setDescriptor`, `updateMemberDelegation` self-grant for Gemini egress. |
| `js/t3-panel.js` | The demo page's Private Briefs panel. Fetches the trust-anchor proof, computes the current brief's expected content address locally (SubtleCrypto, no network), and generates the exact CLI commands + brief file. It never sends the brief or any key anywhere. |
| `t3/proof/trust-anchor.json` | Machine-readable proof that the SDK verified the testnet trust anchor live (regenerated by `node t3/cli.mjs verify`). |

Sage core files (`index.html`, `style.css`, `js/feeds.js`, `js/analysis.js`, `js/app.js`, `js/anchor.js`, `js/config.js`, `contracts/ResearchAnchor.sol`, `PLAN.md`) are carried over unchanged from [sage-base-stocks](https://github.com/coral-fox-12/sage-base-stocks) except for the added T3 panel import.

## Setup

```bash
npm install
# 1. Get a T3N API key from the Terminal 3 claim page (shown once — copy it).
export T3N_API_KEY=<your key>          # never in a file, never printed
node t3/cli.mjs verify                 # no key needed; writes t3/proof/trust-anchor.json
node t3/cli.mjs connect                # authenticate, print the tenant DID
node t3/cli.mjs setup                  # register contract + create private maps + descriptor
export T3_GEMINI_KEY=<your Gemini key> # used once to seed the secrets map
node t3/cli.mjs seed-gemini            # stores it; verifies by read-back; never prints it
node t3/cli.mjs grant                  # self-grant: private-rewrite may reach generativelanguage.googleapis.com
```

Then use it with a real brief (generate one on the demo site, or build one locally):

```bash
node t3/cli.mjs seal-brief --file sage-brief-NVDA.json --symbol NVDA
# -> { "key": "<64-hex>", "symbol": "NVDA", "bytes": 1234, "map": "z:<tid>:briefs", "sealed_at_secs": ... }
node t3/cli.mjs private-rewrite --key <64-hex>
# -> rewritten brief text + token counts. Only the text comes back.
node t3/cli.mjs status                 # contract, maps, secrets presence
node t3/cli.mjs logs --limit 20        # contract debug logs (empty unless log quota is on)
```

Re-running `setup` is safe: it skips re-registration when the same WASM is already registered (re-registering allocates a *new* contract id, so the id is persisted in `t3/state.json` — local state, not committed). Bumping the contract version requires bumping `CONTRACT_VERSION` in `t3/lib.mjs` and `contract/Cargo.toml` together.

## Security notes

- No secret is ever committed. `t3/state.json` holds only tenant metadata (contract id, version, hashes) and is gitignored. API keys live only in the environment (CLI) or the enclave-held secrets map.
- The contract's log lines never contain key material or brief content — only the seal key (a hash), symbol, byte counts, and token counts.
- Map ACLs: both `secrets` and `briefs` are `visibility: "private"` with readers/writers scoped to the contract id only. The tenant can still seed entries via the control plane; no other contract can read them.
- Outbound HTTP is authorized by the calling user (member-delegation self-grant), not the contract — per the T3 docs. Without the grant, `private-rewrite` fails with `host/http.egress_denied`.
